外部AIに精査を頼む時、**コードを渡す便と、「利用者がこれまでに出した指摘の全リスト」だけを渡す便を分けて出す**。後者は前者では出ない種類の欠陥を出す。

2026-08-01の野球ゲームで実証（オーナー提案）。同じ対象に2便を並行で出した。
- **コード便**（守備判断の抜粋840行）→ 14件。実装の分岐の誤り
- **履歴便**（利用者の指摘80件を時系列・原文で、**コードは渡さない**）→ 6件の未報告予測。うち**「第3アウトより先に本塁を踏んでいない走者が得点する」（タイムプレー）が実在**し、48場面の機械検査で再現した

タイムプレーの欠陥は**コード便では出なかった**。コードを読むと「得点の数え方」は自己整合しているように見えるが、指摘の履歴を読むと「判定が物理的な到達より先に確定する」という作り手の癖が繰り返し現れており、そこから未報告の箇所を当てられた。

**もう1つ効いた仕掛け**: 依頼文に**自分が課したルールを明記し、「破っている箇所があれば指摘してくれ」と書く**。今回は「守備は走者の内部の意図(goal)を読んではいけない」と書いたところ、重大度・高の指摘として自分の違反が返ってきた。**書かなければ相手はその規約を知らないので、永久に検出されない。**

**Why:** コードレビューは「書かれているもの同士の整合」しか見られない。利用者の指摘の履歴は**症状の分布**であり、そこには作り手が繰り返す思い込みが現れる。母集団が違うので、出てくる欠陥も違う。

**How to apply:**
1. 高ステークスの精査は**2便に分ける**。コード便＝実装の分岐、履歴便＝作り手の癖からの予測。並行で出す
2. 履歴便には**コードを渡さない**。渡すと照合作業に退化する。「まず履歴だけで予測し、その後で必要ならコードを見る」と順序を指定する
3. 依頼文に**自分の設計ルール・不変条件を明記**し、違反の指摘を求める。あわせて**機械検査で潰し済みの項目を「指摘不要」として列挙**すると、重複が減って密度が上がる
4. 予測は仮説なので、**受け取ったら必ず機械検査で再現を試みる**。今回も6件中1件が実在、1件は該当なしと確定できた
5. 履歴リストは普段から作れる。**指摘を受けたらその場で原文を残しておく**と、この便がいつでも出せる
