シミュレーションで「うまくいく確率」を引いて結果を決める仕掛けを入れる時、**その確率が推定に使う情報より正確な情報が手元にある場面では、確率を使わない**。使うと物理的にありえない結果が混ざり、それが見た目の不自然さの主因になる。

2026-08-02の野球ゲームで実証。「野手が間に合ったか」を確率で判定する仕掛けを入れた（ぎりぎり届く打球が毎回捕られるのを防ぐため）。その確率は**野手の定位置からボールまでの距離**で見積もっていた。ところが判定する瞬間には**野手の実際の座標**が分かっている。結果、**足元0.3ftに転がってきたゴロが素通りして25ft後方まで行く**場面が打球の25%で発生し、利用者から「直線で行くせいで後逸する」と2度指摘された。

修正は「確率の適用範囲を狭める」ではなく**確率の廃止**。抜けるかどうかは足の速さと距離（実座標）だけで決まるようにし、確率で作っていたぶんの安打は**守備範囲そのもの**（反応時間0.22→0.28秒＝実測の一歩目）で作り直した。

**Why:** 確率は「分からないことを平均で埋める」道具。分かっていることの上に被せると、既知の事実と矛盾する出目が必ず一定割合で出る。その矛盾は数字の上では小さく見えても、見ている人には「バグ」としてはっきり分かる。

**How to apply:**
1. 確率判定を入れる前に「この判定に必要な情報は、この瞬間に本当に手に入らないか」を確認する。手に入るなら実値で決める
2. 確率が使う代理指標（定位置・平均・過去の傾向）と、実際に確定している値がズレる場面を1つでも挙げられるなら、その場面は確率の適用外にする
3. 確率を外して数字が合わなくなったら、**確率を戻すのではなく、本来のパラメータ（範囲・速さ・時間）で作り直す**（[[feedback-fixing-a-model-invalidates-its-calibration]] と同じ向き＝測れる側を直す）
4. 「入れた本人が不自然さの原因になっている」ことがあるので、症状を数値で測る時は自分が足した仕掛けも容疑者に入れる（[[feedback-measure-the-symptom-not-the-mechanism-you-fixed]]）
