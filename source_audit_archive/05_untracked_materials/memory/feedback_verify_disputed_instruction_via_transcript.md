/compact後、ユーザーが「codex生成の図解が私が求めていたものとずれているから再生成してほしいといったはずですが」と過去の指示を主張したが、直前の会話要約にはその指示が見当たらなかった（要約にあったのは「本文の解説が求めていた内容とずれている」という**別の**訴えへの対応記録だけ）。

**Why:** 圧縮された要約は元の発言のニュアンスを削ぎ落とすことがある（今回は「図解は追加されたが本文の解説が足りない」という当時の指摘が、ユーザーの中で後から「図解自体がずれている」という主張にリフレームされていた可能性がある）。ここで①要約を盾に「言っていません」と反論する②主張をそのまま鵜呑みにして的外れな再生成に着手する、のどちらも危険——①はユーザーを疑う形になり信頼を損ない、②は「何がずれているか」を特定しないまま重い工程（Codex再生成は手動投入込み）に入ると無駄骨になる。

**How to apply:**
- 過去の指示の有無が自分の要約と食い違う時は、Read/Grepで**生トランスクリプト**（`~/.claude/projects/.../*.jsonl`）を検索して事実確認する。jsonlは1行が会話ターン全体を含み巨大なことが多いので、Grepで行番号を特定してから`Read`に`offset=行番号, limit=1`を指定して該当行だけ読む（全文読み込みはトークン超過で失敗する）
- **★発火条件はこの1行（2026-08-05に条件を拡張）**: 「争点の事実確認」に限らず、**過去のユーザー発言を材料にする作業すべて**——指摘リスト作成・要望の棚卸し・監査・handoff作成・「今まで言ったことを全部」系——でこのメモリを発火させる。2026-07-23版は description を「ユーザーが『言ったはずですが』と主張した時」と書いたため、2026-08-05の全量抽出タスクで**発火しなかった**（＝下の知識は既に持っていたのに同じ取りこぼしを再演した）。範囲を狭く書いた発火条件は、知識があっても効かない
- **★ユーザー発言の抽出は`type=user`レコードだけでは不完全（2026-07-23発見・2026-08-05再演）**: CCの作業中に送られた割り込みメッセージは**`type=queue-operation, operation=enqueue`**（`content`に生テキスト）と**`type=attachment, attachment.type=queued_command`**（`attachment.prompt`に生テキスト、`origin.kind=human`）として記録され、userレコードには現れないことがある。トランスクリプト監査・発言全量抽出では3つの型すべてを拾い、本文先頭200文字で重複除去する。またAskUserQuestionの回答はtool_result内の「The user answered」文字列で拾う。
  - 実害1（2026-07-23）: 監査の初回抽出がqueue型を全て取りこぼし、「毎回毎回スリープが原因なのに壊れていると言って時間を割くのをやめてください」等の重要指示が見えていなかった
  - **実害2（2026-08-05・野球ゲーム）: オーナー「私の指摘をすべて一つのmdファイルにまとめ」に対し、userレコードのみの抽出で57件→3型すべてで152件。取りこぼし95件＝全体の62%。しかもオーナーは2026-08-01に一度「今までの私の指摘リストをすべて作り」と依頼しており、その時のリストも同じ理由で不完全だった疑いが濃い（＝「レビューしたのに再発する」の一因を自分で作っていた）**
- **全量抽出をやったら「取りこぼしの監査」を必ずセットで回す**: フィルタで落としたレコードを別ファイルに出し、落とした理由（stop-hook/コマンド/自動要約 等）ごとに件数と先頭160文字を並べて目視する。今回はこの監査でqueue型の取りこぼしに気づいた。フィルタを書いたら、そのフィルタが何を捨てたかを必ず見る
- **セッションとjsonlファイルの対応は思い込みで決めない**: プロジェクトdirはcwd別に分裂しており（Hub直下・金融・投資・大学系・worktree等）、mtimeは後からのアクセスでも更新される。セッション固有の語（固有名詞・事件名）でgrepして特定する。見つからないセッションもある（今回=v7.9承認セッションのローカルログは全dir検索でも発見できず）——その場合は「トランスクリプト監査不能」と正直に報告し、handoff・メモリ・タスク台帳という二次記録でカバーされている範囲を明示する
- 確認の結果、ユーザーの主張と実際の過去発言に食い違いがあっても、それを指摘して終わらせない。**実データ（今回は生成済み画像を実際に開いて本文の数値と座標を照合）を調べ、ユーザーの「今」の懸念に実体があるか検証する**。今回は既存3枚（No.11/30/31）自体は本文と正確に一致していたが、元々「難しい」と挙げられた6項目のうち3項目には図解が1枚も存在しないという具体的なギャップが見つかった——「言った/言わない」の水掛け論より、この実体の発見の方が生産的
- 調べた結果「何がずれているか」に複数の候補が残る（今回は第6・7・8講のどの図解を指すか、事前には特定できなかった）場合は、**推測で1つに決め打ちして再生成に着手しない**。調査で分かったこと（正確だった図・カバレッジの穴）を先に提示した上で、調査から得た具体的な候補をAskUserQuestionの選択肢にして絞る（白紙の「どれですか」ではなく、調べ尽くした上での絞り込みにする）
