「変化したか」をしきい値で判定する時は、**何もしない時にその量がいくつなのかを先に出す**。基準値がしきい値の向こう側にあると、**効いている修正が「まったく効いていない」と出る**。

2026-08-04の野球ゲームで実証。「走者がスタートしたか」を `goal > 塁 + 0.01` で数えたところ、打球の方向を変えても**全条件で100%**になった。修正が丸ごと効いていないように見えたので、正しい実装を疑って書き換えかけた。実際は**走者は常にリード（0.085）を取っており**、静止している走者でも `goal = 2.085` だった。しきい値0.01がリードの内側にあり、「動いていない」も「動いた」も同じ判定になっていた。`+0.5` にしたら、狙いどおり0%と100%に分かれた。

**Why:** しきい値は「変化なし＝0」を暗黙に仮定して置きがちだが、実際の系では待機状態にも値がある（リード・オフセット・初期値・ノイズ床）。その値を確認せずにしきい値を置くと、測定器が最初から振り切れている。

**How to apply:**
1. しきい値を置く前に、**入力を与えない条件を1回流して基準値を出す**。しきい値はその外側に置く
2. 全条件で同じ結果（100%／0%）が出たら、まず**測定側を疑う**。実装が全条件で同じ挙動をすることは、確率的な系ではむしろ稀
3. 疑ったら、判定した真偽値ではなく**生の値をそのまま出して見る**（今回は goal の実数と担当野手を並べた瞬間に分かった）
4. 「効いていない」と結論して実装を書き換える前に、この2つを必ず通す
