判断を行う主体（AI・守備側・戦略ロジック）が、**その立場からは本来見えないはずの情報**を参照していないかを、設計時に明示的に確認する。見えない情報を使うと、挙動が不自然になるだけでなく、評価そのものが無意味になる。

2026-07-31の野球ゲームで、オーナーから「守備の思考が走塁の思考と独立していないのがおかしい。守備は守備でその場で最適な行動をとるべき」と指摘された。実際、守備の送球先を**走者の内部変数（どこへ行くつもりか＝goal）**から決めていた。結果:
- 走者が本塁を狙う「つもり」になった瞬間に、守備が本塁へ投げる
- 走者がリードで少し動いただけで「走り出した」と誤認して無用な送球
- 走者側の操作を変えると守備の行動まで連動して変わる

**見えるものだけ**（走者の現在位置・走っている向き・速度、塁の占有状況、アウト数）で判断するよう作り直したところ、送球先が野球として正しくなった（走者なし→一塁 / 一塁走者→二塁封殺 / 一二塁→三塁封殺 / 満塁→本塁封殺 / 三塁走者のみ→一塁）。

**Why:** 「相手の意図が見えている」判断は、実装者からは自然に見える（同じメモリ上にあるので参照できてしまう）。しかし外から見ると超能力であり、ユーザーには「動きがおかしい」としか映らない。オーナーはこれを一目で見抜いた。

**How to apply:**
1. 判断ロジックを書く前に、**その主体が観測できる情報の一覧**を先に決める。それ以外は参照禁止とコメントに明記する。
2. 実装後、判断関数が読んでいる変数を洗い、観測可能リストに無いものが混ざっていないか確認する。
3. **相手側の操作を変えた時に、こちらの判断が変わらないこと**を検査項目にする（変わるなら見えない情報を読んでいる）。
4. 同じ型は投資・分析でも起きる。**決定時点で入手できない情報を判断に使っていないか**（先読み・未来の値・確定後の結果）は同じ検査で捕まえられる。バックテストの「カンニング」はこの一般形。
