保存則・整合性・停止性のような不変条件は**帳簿の検査**であり、「その分野として正しく動いているか」は一切見ていない。利用者が見ているのは**振る舞いと出来事の順序**なので、帳簿がゼロ違反でも指摘は止まらない。

2026-07-31の野球ゲームで、オーナーから「どうしてあなたのチェックではこの大量のミスを見つけられないのか」と問われた。直前まで「2592場面で違反ゼロ」を報告していたのに、報告された不具合は7件中7件が検査の外だった:

| オーナーの報告 | 帳簿検査の結果 |
|---|---|
| 中継が刺せない塁に投げた | 走者数は合う→通過 |
| 走者が進塁キーで動かない | 走者数は合う→通過 |
| 二塁を踏む前に併殺成立 | アウト2で合う→通過 |
| フライのアウトカウントが3秒遅れる | 最終値は正しい→通過 |
| 野手が捕った時点で三塁打確定 | 走者数は合う→通過 |

**Why（4つの機構）:**
1. **正解表を書いていなかった。** 「この場面で誰がどこへ投げるべきか」「封殺できるのはいつか」「アウトカウントはいつ増えるべきか」を一度も書き出していない。帳簿検査は正解表なしで書けるので、そちらだけ書いていた。
2. **自分の判定を自分の検査の正解に使っていた。** 塁打数を「打球回収の秒数」で決め、検査もその同じ値と突き合わせていた＝間違った値は必ず通る（[[feedback-display-and-judgment-must-share-one-computation]] の裏面。同じ計算を共有すると照合は無意味になる）。
3. **最終状態しか見ていなかった。** 利用者が見るのは順序（踏む前に投げた／捕ってから3秒後に数が増えた）。
4. **1場面1入力で回していた。** 実際の利用者はプレーの途中で操作を変える。

**How to apply:**
1. 帳簿の不変条件（保存・停止・上限）に加えて、**「その分野の正解表」を先に書く**。表が書けない分野なら、そもそも仕様が決まっていない。
2. **順序の検査を入れる**: 出来事Aと表示Bの時間差が閾値内か、Aの前にBが起きていないか。最終状態の比較では絶対に出ない。
3. **判定に使っていない経路で再計算して突き合わせる**（表示ラベル vs 実際の到達位置、など）。
4. **入力を途中で切り替える場面**を直積に含める。
5. 検査を足したら、**それが新しく何を見つけたかで検査の価値を測る**。今回は5つ足した瞬間に未報告の欠陥107件を検出した（本来の担当者が打球を追うと誰も塁に入らない）。何も見つからない検査は、通っても情報がない。
