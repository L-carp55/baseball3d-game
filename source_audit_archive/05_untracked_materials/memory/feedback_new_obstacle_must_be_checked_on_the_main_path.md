**割り込む種類の追加**——視界を遮る物体、処理を打ち切る上限、失敗を宣言する判定——を入れた時は、**その機能の指標だけで合格にしない**。一番よく使う画面・動線を1回通して、そこに割り込んでいないかを見る。

2026-08-04の野球ゲームで4件連続した。いずれも「追加した機能自体は測って正しかった」のに、既存の主要動線を壊していた。

| 追加したもの | 測って合格にした指標 | 実際に壊した所 |
|---|---|---|
| バックネット | 打球の到達距離 107ft→61ft | **打席カメラの真正面に立ち、内野が見えなくなった** |
| 高い送球=悪送球 | 頭上を越える送球が通過する | 肩の弱い選手の山なり送球が全部エラー記録に |
| プレー12秒で打ち切り | 決着しない場面が終わる | 追い込み中の挟殺が強制セーフに |
| 返球だけになったら即終了 | 無駄な待ち時間が消えた | フライ捕球直後に閉じ、タッチアップが不可能に |

**Why:** 追加した本人は「その追加が解く問題」の視点で検証を組む。割り込む種類の追加は定義上、**他の場面の途中に入り込む**ので、その視点からは見えない。特に3D・UIでは「置いた物が視界に入る」ことを数値で測る手段がなく、1枚見れば即分かる。

**How to apply:**
1. 遮蔽物・上限・失敗判定を足したら、**一番よく使う画面で1回描く／1回通す**。3Dなら主カメラで1枚撮る、UIなら既定の画面を開く
2. 「この追加が割り込みうる既存の場面」を1つ挙げてから実装する。挙がらないなら割り込む種類ではない
3. 打ち切りの上限を足す時は、**すでに自前の上限を持つ処理**（挟殺・アニメーション・リトライ）を先に洗い出して除外する
4. 失敗を宣言する判定は、**正常だが極端な入力**（弱肩の山なり送球、非常に遅い端末）で誤発火しないか確認する
